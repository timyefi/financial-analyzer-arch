1. 全景概览：两个 Skill 是什么

你想解决什么问题？

作为信评研究员，你每天要面对几十份 PDF 财报（动辄 200+ 页），手动提取数据、计算指标、撰写分析——耗时且容易遗漏。这两个 Skill 就是为此而生：

financial-analyzermeta-financial-analyzer
一句话定位 通用财务分析执行引擎 定制训练引擎（母 Skill）
做什么 14 Agent × 5 阶段，把财报 PDF 变成深度分析报告 通过对话了解你的需求，生成专属分析规则，再指挥执行引擎干活
产出 analysis_report.md + workbook_master.xlsx client_rules.md（你的专属规则）→ 驱动执行
知识库 通用 13 维度（v2.6.1） 通用 + 你的定制层（阈值/优先级/IF-THEN）
门禁 无，给数据就能跑 出厂 = TEMPLATE，未完成定制禁止执行
类比理解 financial-analyzer 是"通用分析工人"——给他财报，他按标准流程出报告。
meta-financial-analyzer 是"培训师 + 调度员"——先问清你要什么风格、关注什么指标、什么阈值触发预警，然后训练工人按你的规矩干活。

架构关系

meta 自包含了 financial-analyzer 的全部代码和知识库（modules/financial_analyzer/），不是"引用"而是"包裹"。

验证清单

在 AI Agent 对话框中输入以下内容，Agent 会自动帮你检查：

# 对 AI 说： "帮我检查财务分析环境是否就绪" # AI 会依次验证： # ✓ MinerU token 有效性 # ✓ Python 版本 ≥ 3.10 # ✓ 输出目录可写 # ✓ 依赖包完整（openpyxl, requests 等）

3. 首次定制：Onboarding 对话

这是 meta-financial-analyzer 的核心环节。首次使用时，AI 不会直接跑分析，而是先跟你聊 4 轮，搞清楚你的需求：

环境验证

AI 自动检查 MinerU token、Python 依赖、代理、输出目录。全部通过才进入下一轮。

你需要做：无，等待即可。

定位：你是谁？

AI 会问你的行业（城投/产业/地产/港股）、角色（信评/投资/风控）、覆盖主体数量、分析频率。

你需要做：用自然语言描述，比如"我做城投信评，覆盖 80 个省级+市级平台，每周分析 3-5 份"。

深挖：你关注什么？

AI 追问指标优先级（融资成本 > 偿债 > 现金流？）、风险阈值（资产负债率多少算预警？）、行业特殊规则。

你需要做：给出你的判断标准，比如"资产负债率 > 65% 关注，> 75% 预警，> 85% 禁用"。

深度定制：你还可以投喂自己的过往评级报告、知识笔记、调研纪要等材料。AI 会从中提取你的分析框架、行文风格、关注重点，将其融入知识库，让后续分析完全贴合你的方法论。

固化：确认规则

AI 把你的回答整理成 client_rules.md，逐条念给你确认。确认后状态从 TEMPLATE → ACTIVE。

你需要做：审阅确认，或要求修改某条。

对话示例（城投分析师）

AI
你好！我是你的财务分析定制引擎。在开始之前，我想先了解你的工作场景。你主要分析哪类主体？覆盖多少个？频率如何？
你
我做城投信评，主要看省级和市级平台，大概覆盖 80 个主体。每周分析 3-5 份年报或半年报。
AI
明白了。城投平台的话，你最看重哪些维度？比如融资成本、偿债能力、现金流、盈利能力——你会怎么排优先级？另外，资产负债率到什么水平你会开始警惕？
你
融资成本最重要，其次是偿债和现金流。盈利对城投意义不大。资产负债率 65% 以上关注，75% 预警，85% 以上基本不碰。另外政府补助不能算核心盈利，互保链必须穿透。
AI
收到。我整理一下你的规则：

① 优先级：融资成本 > 偿债 > 现金流 > 盈利
② 阈值：资产负债率 65%/75%/85% 三档
③ 特殊规则：政府补助不计核心盈利；互保链须穿透

还有补充吗？确认后我就生成你的专属规则文件。

深度定制：投喂你的专属材料

除了对话定制，你还可以向 AI 投喂自己的历史积累，让整个分析框架真正"像你一样思考"：

可投喂材料AI 从中提取什么效果
过往评级报告你的分析框架、章节结构、措辞风格、结论逻辑生成的报告贴合你的行文习惯
知识笔记 / 方法论你总结的行业规律、特殊指标、判断标准知识库叠加你的专属维度
调研纪要你关注的定性因素（管理层态度、政府支持意愿等）分析中自动纳入定性判断
内部信评模板你所在机构的报告格式、必填字段、审批要求产出直接符合内部规范
历史预警案例你踩过的坑、识别过的风险信号IF-THEN 规则更精准
投喂方式 直接把文件发给 AI，说"学习这份报告的分析框架"或"把这个笔记里的指标加入知识库"。AI 会解析内容、提取规则、写入 knowledge_base.json 和 client_rules.md，下次分析立即生效。
定制完成后 规则保存在 config/client_rules.md，首行标记 CUSTOMIZATION_STATUS: ACTIVE。之后每次分析都会自动注入这些规则。想改？直接说"把资产负债率预警线改成 70%"即可。

4. 全流程实操：从 PDF 到报告

定制完成后，你只需说一句"分析 XX 公司 2024 年报"，AI 就会自动跑完 5 个阶段：

阶段 0：初始化

AI 读取你的 client_rules.md，确认分析参数（主体名、报告期、行业模板）。

阶段 1：下载财报

多源路由自动寻找 PDF：

数据源覆盖优先级
中国货币网 (chinamoney)银行间市场发债主体最高
巨潮资讯 (cninfo)A 股上市公司次高
港交所 (hkex)港股上市公司港股专用
本地缓存已下载过的 PDF优先复用

阶段 2：MinerU 智能解析

PDF → Markdown，VLM 引擎识别表格结构、公式、页眉页脚。

200 页分段陷阱 MinerU 单次最多处理 200 页。超过的财报会被自动分段解析再合并。如果你看到输出目录有 _part1.md、_part2.md，说明触发了分段——AI 会自动合并，无需手动干预。

你会看到：输出目录出现 parsed_report.md（完整的 Markdown 财报）。

阶段 3：14 Agent 流水线分析

这是核心环节，14 个 Agent 分 5 个子阶段依次执行：

子阶段Agent做什么产出
提取总结Agent-01扫描附注，生成章节地图section_map.json
制作底稿Agent-02三大主表提取agent02_main_statements.xlsx
Agent-03资产类附注agent03_asset_notes.xlsx
Agent-04负债权益附注agent04_liability_equity_notes.xlsx
Agent-05损益及其他附注agent05_profit_loss_other_notes.xlsx
Agent-06合并 + 勾稽校验workbook_master.xlsx
指标 + 分析Agent-07知识库 × 底稿 → 指标体系indicator_framework.json
Agent-08偿债能力深度分析—
Agent-09盈利与运营分析—
Agent-10现金流与杠杆分析—
Agent-11有息债务 + 融资成本—
Agent-12合并 + 交叉验证workbook_analysis.xlsx
关键公式：融资成本（现金口径） (付息支出 - 付息现金流 - 股东分红) / 平均有息债务
这是 Agent-11 的强制公式，不允许用简化版（利息支出/有息债务）。

你会看到：输出目录出现 workbook_master.xlsx（数据底稿）和 workbook_analysis.xlsx（分析底稿），所有派生指标都是公式驱动，不是硬编码数字。

阶段 3 续 + 阶段 4：报告生成

Agent-13 逐章撰写深度分析报告，覆盖 8 大维度：

#维度核心问题
1总览与基本信息这家主体是谁？做什么？
2利润与盈利质量赚钱能力如何？利润含金量？
3现金流与短债现金够不够还短期债务？
4债务与资本结构杠杆多高？债务结构合理吗？
5存货与资产质量资产有没有水分？
6受限资金、担保、或有事项有没有隐性风险？
7管理层支持与持续经营股东/政府会不会兜底？
8专题修正项行业特殊问题（如城投互保链）

阶段 5：知识库更新

Agent-14 把本次分析中发现的新指标、新阈值、新规则增量写入知识库。下次分析会更深入。

最终产出 analysis_report.md — 完整的深度分析报告（通常 8000-15000 字）
workbook_analysis.xlsx — 全部指标的数据底稿（公式可追溯）
knowledge_delta.json — 本次新增的知识条目

5. 14 Agent 详解

每个 Agent 都有明确的输入、任务和输出。它们像流水线工人一样依次作业：

Stage 1 · 提取总结

Agent-01 附注扫描

扫描 200+ 页 MD，识别哪些章节是"应收账款附注""借款附注"等，生成章节地图。

输入：parsed_report.md → 输出：section_map.json
Stage 2 · 制作底稿

Agent-02 主表提取

从 MD 中提取资产负债表、利润表、现金流量表的标准科目数据。

输入：section_map + MD → 输出：agent02_main_statements.xlsx
Stage 2 · 制作底稿

Agent-03 资产类附注

提取应收账款账龄、存货构成、固定资产折旧、无形资产等明细。

输入：section_map + MD → 输出：agent03_asset_notes.xlsx
Stage 2 · 制作底稿

Agent-04 负债权益附注

提取借款明细（银行/债券/非标）、应付账款、所有者权益变动。

输入：section_map + MD → 输出：agent04_liability_equity_notes.xlsx
Stage 2 · 制作底稿

Agent-05 损益及其他

提取收入构成、费用明细、政府补助、关联交易、担保事项。

输入：section_map + MD → 输出：agent05_profit_loss_other_notes.xlsx
Stage 2 · 制作底稿

Agent-06 合并校验

把 02-05 的数据合并为 workbook_master，执行勾稽校验（资产=负债+权益等）。

输入：4 份 xlsx → 输出：workbook_master.xlsx + merge_log.json
Stage 3 · 指标体系

Agent-07 指标设计

读取知识库 13 维度 × 底稿数据，设计本次分析的指标方案（含公式定义）。

输入：knowledge_base + workbook → 输出：indicator_framework.json
Stage 3 · 深度分析

Agent-08 偿债能力

流动比率、速动比率、现金比率、短期偿债压力测试。六层分析深度。

深度：当期值→同比→环比→趋势→异常→情景
Stage 3 · 深度分析

Agent-09 盈利与运营

毛利率、净利率、ROA、ROE、应收账款周转、存货周转。

城投特殊：政府补助剥离后看核心盈利
Stage 3 · 深度分析

Agent-10 现金流与杠杆

经营现金流/短债、自由现金流、资产负债率、EBITDA 利息保障倍数。

关键：现金流是偿债的第一来源
Stage 3 · 深度分析

Agent-11 有息债务 + 融资成本

有息债务结构（银行/债券/非标占比）、期限分布、融资成本（现金口径强制公式）。

公式：(付息支出-付息现金流-分红)/平均有息债务
Stage 3 · 合并验证

Agent-12 交叉验证

合并 08-11 的分析结果，交叉验证一致性（如偿债指标与现金流结论是否矛盾）。

输入：4 份分析 → 输出：workbook_analysis.xlsx
Stage 4 · 报告

Agent-13 报告撰写

逐章撰写 8 维度深度报告，引用底稿数据，标注证据等级（A/B/C 级）。

产出：analysis_report.md（8000-15000 字）
Stage 5 · 进化

Agent-14 知识库更新

比对本次发现与现有知识库，增量写入新指标/新阈值/新规则。

产出：knowledge_delta.json → 知识库 v2.6.x+1

6. 知识库进化机制

知识库是整个系统的"大脑"——Agent-07 设计指标时必须完整读取全部 13 维度，不得自行发明指标。每分析一份财报，知识库就进化一次：

13 个知识维度

#维度对应 Agent典型指标
1偿债能力 (solvency)Agent-08流动比率、速动比率、现金比率
2运营效率 (operation)Agent-09应收账款周转天数、存货周转率
3盈利能力 (profitability)Agent-09毛利率、净利率、ROE
4现金流 (cashflow)Agent-10经营现金流/短债、自由现金流
5杠杆 (leverage)Agent-10资产负债率、权益乘数
6有息债务 (IBD)Agent-11有息债务率、短期占比
7EBITDAAgent-10/11EBITDA 利息保障倍数
8现金分析Agent-10受限资金比例、现金覆盖率
9勾稽校验Agent-06资产=负债+权益、现金流勾稽
10港股规则Agent-07港股特殊披露处理
11LGFV（城投）Agent-09/11政府补助剥离、互保链穿透
12房地产Agent-07去化周期、受限资产、担保余额
13数据质量Agent-06/12异常值检测、缺失处理
进化闭环 知识库完善 → 指标体系更丰富 → 分析更深入 → 发现新缺口 → 知识库再完善。
目前已积累 11 个案例（从首例"余姚工业园区"到"万科 2025 半年报"），版本 v2.6.1。

7. 进阶用法 & FAQ

批量分析

对 AI 说"批量分析以下主体：A 公司、B 公司、C 公司的 2024 年报"。每个主体独立执行完整 pipeline，最后输出批量对比表 + 预警列表。

批量铁律 1 对 1 独立执行，严禁循环合并。每个主体有自己的 output 目录，互不干扰。

行业模板对比

模板特有指标适用主体
通用 (general)标准三表 + 基础比率产业类企业
城投 (LGFV)政府补助剥离、互保链、财政依赖度省/市/区县级平台
房地产 (realestate)去化周期、土地储备、预收/合同负债、净负债率房地产开发商
港股港股披露差异处理、港币/人民币换算港股上市主体

常见问题

问题原因解决
MinerU 解析报 401 Token 过期或额度用完 去 mineru.net 重新生成 token
AI 拒绝执行分析 client_rules.md 仍为 TEMPLATE 先完成 Onboarding 对话
底稿勾稽不平 PDF 表格识别错误（合并单元格） 检查 merge_log.json 中的差异项，手动修正 MD
融资成本算出来异常高 有息债务口径不一致（含/不含应付债券） 确认用"现金口径"公式，检查分母是否包含全部有息债务
报告缺少某个维度 财报中确实没有相关披露 正常——Agent 会写"未抽取到"，不会编造数据

修改定制规则

随时对 AI 说：

"把资产负债率预警线从 75% 改成 70%" "增加一条规则：如果非标占有息债务超过 30%，标记为高风险" "把盈利能力的优先级调到最后一位"

AI 会直接更新 client_rules.md，下次分析立即生效。
