01系统总览：分层架构

Financial Analyzer 采用分层 + 单向依赖设计：上层依赖下层，下层对上层无感知。 每一层都可以被替换或单独使用。依赖方向自上而下，任何一层都不 import 上层代码—— 这是"可解耦"的根本保证。

02模块注册表：接口契约一览

每个模块用统一的接口契约（Interface Contract）描述：输入 schema、输出 schema、依赖、独立使用场景。 只要你的上游产出符合下游的输入 schema，就可以任意拼接或替换。

M1 · 多源下载器

L1 · DATA

多源路由自动寻源：chinamoney → cninfo → hkex → 本地缓存。输出标准 PDF + 元数据。

IN  : subject_name, report_period
OUT : raw_report.pdf, download_meta.json
DEP : requests, 网络

M2 · MinerU 解析引擎

L1 · DATA

VLM 智能解析 PDF → Markdown，识别表格结构/公式。>200 页自动分段合并。

IN  : *.pdf（任意来源）
OUT : parsed_report.md
DEP : MinerU API token

M3 · 14-Agent 分析引擎

L2 · CORE

提取 → 底稿 → 指标体系 → 深度分析 → 报告。Agent 间通过文件传递状态，可截断运行。

IN  : parsed_report.md
OUT : workbook_master.xlsx, analysis_report.md
DEP : knowledge_base.json, templates/

M4 · 知识库

L2 · CORE

13 维度指标/公式/阈值的唯一权威来源。可独立查询、写入、版本管理、回滚。

IN  : 分析发现（knowledge_delta.json）
OUT : knowledge_base.json（v2.6.1）
DEP : 无（纯 JSON）

M5 · Pipeline 编排器

IN  : 任务配置（subject, period, mode）
OUT : pipeline_state.json, 校验报告
DEP : M1~M4

M6 · 定制层（meta）

L4 · CUSTOM

对话式 onboarding，生成 client_rules.md 注入引擎。可完全跳过。

IN  : 用户对话 / 投喂材料
OUT : client_rules.md（TEMPLATE→ACTIVE）
DEP : M3（注入目标）

03模块 M1：多源下载器

modules/download/discovery.py 实现"多源路由"：按优先级依次尝试各数据源， 命中即停。每个数据源是一个独立适配器（sources/*.py），新增数据源只需实现统一接口。

路由优先级

优先级数据源覆盖范围适配器
1本地缓存已下载过的 PDF（按 subject+period 哈希命中）sources/local.py
2中国货币网 chinamoney银行间市场发债主体（财报/评级报告）sources/chinamoney.py
3巨潮资讯 cninfoA 股上市公司定期报告sources/cninfo.py
4港交所 hkex港股上市公司披露sources/hkex.py

输出 schema

json 
// download_meta.json
{
  "subject": "XX市城市建设投资集团",
  "report_period": "2024A",
  "source": "chinamoney",
  "pdf_path": "output/xx城投_2024A/raw_report.pdf",
  "page_count": 236,
  "downloaded_at": "2026-07-30T10:12:00+08:00",
  "checksum": "sha256:…"
}

独立使用示例

只需要下载 PDF、不需要后续分析时，直接调用下载器：

python 
from modules.download import discovery

# 只下载，不触发解析和分析
result = discovery.fetch(
    subject="XX市城市建设投资集团",
    period="2024A",
    out_dir="D:/output",
)
print(result["pdf_path"])   # → D:/output/xx城投_2024A/raw_report.pdf
替换策略 如果你已有 PDF 获取渠道（Wind 导出、内部系统），直接把文件放到 output/{subject}_{period}/raw_report.pdf 并写好 download_meta.json，下游 M2 即可无缝衔接——下载器完全可跳过。

04模块 M2：MinerU 解析引擎

modules/mineru/mineru_v2.py 将 PDF 转为结构化 Markdown。 核心是 VLM（视觉语言模型）引擎，对复杂表格、跨页表格、财务公式的还原度显著高于传统 OCR。

处理管线

200 页分段策略

MinerU 单次请求上限 200 页。超长财报（常见于港股年报 300+ 页）触发自动分段：

步骤动作产出
1检测页数 > 200，按 200 页切分 PDFpart_001.pdf … part_00N.pdf
2各段并行提交 MinerU（async）part_001.md … part_00N.md
3按页码顺序合并，修复跨段表格parsed_report.md
4质量校验（目录完整性 / 表格闭合）parse_log.json

输出 schema（parsed_report.md 约定）

Markdown + GFM 表格 章节层级 = PDF 标题层级 页码锚点 [p.N] 表格保留合并单元格语义
替换策略 解析层是最容易被替换的模块。只要你的 PDF→Markdown 工具输出满足上述 schema （尤其是表格必须为 GFM 格式、保留章节层级），把结果命名为 parsed_report.md 放入输出目录，Agent 引擎即可直接消费。 常用替代：Marker、Docling、自研解析器。

05模块 M3：14-Agent 分析引擎（核心）

这是整个系统的价值核心。14 个 Agent 按 5 个阶段组织，Agent 之间不直接通信， 全部通过文件传递状态——这意味着你可以在任意 Agent 边界截断、注入、或替换某个 Agent。

Agent 拓扑（DAG，非线性）

关键公式契约：融资成本（现金口径，Agent-11 强制）

Agent-11 计算融资成本时必须使用现金口径公式，禁止使用简化版（利息支出/有息债务）：

formula 
融资成本 = (付息支出 - 付息现金流 - 股东分红) / 平均有息债务

其中：
  付息支出     ← 利润表·财务费用附注
  付息现金流   ← 现金流量表·分配股利/偿付利息支付的现金
  股东分红     ← 现金流量表·分配股利支付的现金
  平均有息债务 = (期初有息债务 + 期末有息债务) / 2
分析深度六层模型（Agent-08~11 通用）

每个分析 Agent 对每个指标执行六层递进分析：

层级内容示例
L1 当期值指标当前数值流动比率 = 1.23
L2 同比变动较上年同期-0.15
L3 环比变动较上一报告期-0.08
L4 趋势判断3~5 年趋势方向持续下行
L5 异常识别偏离行业/历史均值低于行业中位数 0.4
L6 情景分析压力情景推演若短债+20%，覆盖率降至 0.9
8 大分析维度强制覆盖契约（analysis_dimension_contract.md）

Agent-13 生成报告时必须显式覆盖以下 8 个维度，缺数据须写"未抽取到"，不可跳过：

#维度核心问题
1总览与基本信息主体是谁？做什么？
2利润与盈利质量赚钱能力？利润含金量？
3现金流与短债现金够不够还短债？
4债务与资本结构杠杆多高？结构合理吗？
5存货与资产质量资产有没有水分？
6受限资金/担保/或有事项有没有隐性风险？
7管理层支持与持续经营股东/政府会不会兜底？
8专题修正项行业特殊问题（城投互保链等）

截断运行：只跑部分 Agent

因为 Agent 间靠文件传递状态，你可以在任意边界停下。最常见的截断点：

Agent-01~06 → 只要数据底稿 Agent-07 → 只要指标体系 Agent-01~12 → 要底稿+分析，不要报告 Agent-14 → 单独做知识库增量更新

06模块 M4/M6：知识库与定制层

知识库（knowledge_base.json）是指标、公式、阈值的唯一权威来源。 Agent-07 设计指标体系时必须完整读取 13 个维度，不得自行发明指标。 定制层（meta）则在知识库之上叠加你的专属规则。

知识库结构（13 维度）

知识库独立操作

知识库是纯 JSON，可以脱离分析引擎单独读写：

bash 
# 查看当前知识库版本与案例数
python scripts/show_knowledge_adoption.py

# 写入新的知识条目（增量）
python scripts/write_knowledge_adoption.py --delta knowledge_delta.json

# 回滚到上一版本
python scripts/rollback_knowledge_adoption.py --to v2.5.0

定制层状态机（client_rules.md）

meta 模块通过首行标记管理定制状态，形成一道"门禁"：

state 
TEMPLATE ──(完成 4 轮 onboarding)──▶ ACTIVE ──(用户说"改XX规则")──▶ ACTIVE(更新)
   │                                   │
   └── 禁止执行任何分析任务              └── 每次分析自动注入规则
深度定制：投喂专属材料 除对话外，可直接投喂过往评级报告、知识笔记、调研纪要、内部信评模板、历史预警案例。 AI 从中提取分析框架、行文风格、判断标准，写入知识库与 client_rules.md， 使后续分析完全贴合你的方法论。详见 使用教程 · 深度定制。

07集成模式：三种典型用法

根据需求选择集成深度。三种模式覆盖 90% 的场景——从"全都要"到"只要一块"。

模式 A：全流程（下载 → 解析 → 分析 → 报告）

适合：从零开始分析一个新主体，需要完整报告。

prompt 
# 对 AI Agent 说：
"分析 XX市城市建设投资集团 2024 年报"

# Pipeline 自动执行：
# M1 下载 → M2 解析 → Agent-01~14 → analysis_report.md
# 总耗时约 1.5~2 小时
analysis_report.md workbook_master.xlsx workbook_analysis.xlsx knowledge_delta.json

模式 B：只取数据底稿（跳过分析与报告）

适合：你已有自己的分析框架，只需要结构化财务数据。运行 Agent-01~06 即停。

prompt 
# 对 AI Agent 说：
"把 XX 公司 2024 年报做成数据底稿即可，不需要分析报告"

# 执行：M1 → M2 → Agent-01~06，在 Agent-06 后截断
# 产出：workbook_master.xlsx（三大主表 + 全部附注，公式化）
# 耗时约 30~40 分钟
价值点 即使完全不用它的分析，仅"PDF → 结构化底稿"这一步就能节省 2~3 小时手工录入， 且勾稽校验（Agent-06）会自动发现 PDF 识别错误。

模式 C：只用知识库 + 指标体系

适合：你有自己的数据源和分析流程，只想借用它沉淀的 13 维度指标框架。

python 
import json

# 直接读取知识库，获取 13 维度的指标/公式/阈值定义
with open("knowledge_base.json", encoding="utf-8") as f:
    kb = json.load(f)

# 例：取偿债能力维度的全部指标及公式
solvency = kb["knowledge"]["indicators"]["solvency"]
for ind in solvency:
    print(ind["name"], ind["formula"])

# 或让 Agent-07 基于你的底稿生成指标体系：
# "参考知识库，为这份底稿设计指标体系" → indicator_framework.json
无上游依赖 13 维度指标定义 公式 + 阈值 + 行业规则

耗时1.5~2 小时30~40 分钟< 1 分钟
